Return only one JSON object with one top-level field named "stages".

You write a ReKep relational keypoint constraint program for a single robot arm. The program is a sequence of stages; each stage is solved for an end-effector position that satisfies its constraints, and the robot moves there. Use only the object_id, keypoint_id and region_id values in the observation below. Never emit Python or joint commands.

ROBOT
- One arm with a parallel two-finger gripper that always points straight down with a fixed yaw. The fingers close along the base y axis; the maximum opening is 0.085 m, so an object can be grasped only if its width along base y is below about 0.07 m.
- "$ee" is the point midway between the fingertips. A grasp closes the fingers around whatever is at $ee, so a grasp stage must bring $ee to the grasped object's "object_center_estimate" keypoint (kp_00).
- While an object is held, all of its keypoints translate rigidly with $ee (they do not rotate). Constrain held-object keypoints, not $ee, when an object is being placed.
- Stages are executed one by one and each stage is re-solved on a fresh observation with the same keypoint IDs, so write constraints relative to keypoints and regions. Numeric constants are allowed for offsets, clearances and tolerances, and for heights derived from values in this observation (e.g. an observed support height plus a clearance).
- Free motion between stages automatically rises, travels and descends so the open gripper does not sweep through objects; motion while holding travels at a safe transit height and finishes with a vertical descent onto the stage endpoint. A stage with "motion": "straight" instead moves $ee along a straight line from the previous endpoint; use that only for pushing or sliding, together with path constraints that keep $ee at the intended height.

OBSERVATION
- objects: object_id, label and color (from the perception color palette), shape_hint (box, cylinder or irregular), size_m = [extent along the top face's major axis, extent along its minor axis, height], major_axis_xy (current direction of the major axis in the base x-y plane), centroid_m.
- objects also carry footprint_xy, the current outline of the top face (used by the executor for pushing).
- Object keypoints, all in the base frame in metres: kp_00 kind object_center_estimate (volume center, the grasp point); kp_01 kind top_center; kp_02 kind bottom_center (where the object touches its support); kind top_extreme (outermost top-face points along +/- major and minor axes, e.g. the ends of a bar or the tip of a T stem); kind dinov2_feature (visual feature points).
- regions: static target areas on the table. bounds_min_m/bounds_max_m is an axis-aligned volume from the region surface up to a fixed height; surface_z_m is the surface height; shape_hint, size_m and major_axis_xy describe its outline. Region keypoints (they have region_id instead of object_id): region_surface_center and region_extreme points of the outline. Region keypoints never move.
- The image shows the scene with object IDs drawn next to each object, yellow/cyan dots for object keypoints and magenta dots for region keypoints. Use the image to understand the scene and to match the instruction's words (colors, shapes, positions) to object IDs.

PROGRAM FORMAT
Each stage: stage_id, depends_on (prior stage IDs only), subgoal_constraints, path_constraints, events, and optionally "motion" ("auto" default, or "straight").
Each constraint: constraint_id (unique in the program), expression, relation ("le", "ge" or "eq"), target (number) and tolerance (non-negative number).
Events: {"type":"grasp","object_id":"..."} closes the gripper on that object at the end of the stage's motion; {"type":"release","object_id":"..."} opens it. {"type":"push","object_id":"..."} (the stage's only event, nothing held) moves that object without grasping: the stage's subgoal constraints are written on the pushed object's keypoints (where it must end up), and the executor reaches them by repeated observed pushes with the closed gripper; such a stage needs no $ee constraints and no path constraints. Only one object can be held at a time; release before grasping another. The program may end while still holding an object when the instruction asks to pick up, lift or hold it.

Expressions are a restricted JSON AST of objects with an "op" field. Operators:
constant(value) | vector(value: [x,y,z]) | point(keypoint_id; "$ee" for the end effector) | region_center(region_id) (center of the region's bounds volume: its z is halfway up the volume, not on the surface, so use it for x-y alignment only; heights relative to a region use surface_z_m)
add(left,right) | sub(left,right) | scale(arg,factor) | normalize(arg) | neg(arg)
norm(arg) | distance(left,right) | horizontal_distance(left,right) (x-y distance only) | component(arg, axis: "x"|"y"|"z")
dot(left,right) | angle(left,right) | abs(arg) | min(args) | max(args)
point_plane_signed_distance(point, normal, origin_m) | inside_region(point, region_id) | orientation_error(target_quaternion_xyzw)
All operators return numbers or 3-vectors, never Booleans. inside_region returns the non-negative distance outside the region volume and returns exactly 0 for a point inside it, so always use it with relation "le", target 0 and a small tolerance.
Example: {"op":"component","arg":{"op":"sub","left":{"op":"point","keypoint_id":"object_001.kp_02"},"right":{"op":"point","keypoint_id":"object_000.kp_01"}},"axis":"z"} is the height of object_001's bottom above object_000's top.

GUIDANCE
- Grasp stage: distance($ee, target kp_00) <= ~0.005 with a grasp event. Then a lift stage that raises the held object clearly above everything it must pass over; an object that should be "picked up" or "lifted" should end at least 0.15 m above its starting support.
- Placing into a region: align the held object's kp_00 with the region center in x and y (horizontal_distance to region_center), require its bottom_center inside the region, keep its bottom_center 0.005-0.02 m above the region surface (surface_z_m), then release. Do not require a released object's center to equal the volume center; it settles under gravity.
- Placing one object on another (stacking): the held object's bottom_center must be horizontally aligned with the supporting object's top_center (horizontal_distance <= ~0.005) and 0.005-0.015 m above it (component z of their difference), then release. Build a tower from the bottom up; each object can only rest on objects that are already in place.
- Pushing (when lifting is not allowed, or the object should slide): use one stage with a push event. Constrain the pushed object's keypoints to their goal positions with horizontal_distance, e.g. horizontal_distance(object kp_00, goal point) <= 0.01 plus two or more outline points (top_extreme keypoints) so that the orientation is constrained too. When a region outline has the object's shape, the observation contains region keypoints of kind region_fit_target (fields for_object and for_keypoint): they are where that object's keypoints lie when the object is laid exactly into the outline; pair each with its for_keypoint. Pushing is less precise than grasping (the executor reaches about 1 cm), so give each constraint on a pushed object's keypoints a tolerance of at least 0.01 m. A push keeps the object on its support and cannot change any height, so do not add height (z) constraints to a push stage.
- Region keypoints of kind region_fit_target exist only when an object's outline matches the region; use them whenever the instruction asks to match an outline's position and orientation.
- Keep each subgoal feasible by moving $ee alone, keep tolerances realistic (>= 0.003 m for positions) and avoid contradictory constraints.
