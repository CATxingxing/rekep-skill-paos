# ReKep 仿真 Skill 开发手册（P0）

> 目标：把参考插件 `PhyAgentOS-rekep-real-plugin` 的**仿真 ReKep 能力**，按 PhyAgentOS 最新 Node/Forge 协议重做成一个 Skill，接入 `PhyAgentOS-core`。
> 适用版本：PhyAgentOS `v1.0.0` / `main`；Dora CLI `0.4.1`（dora-message `0.7.0`）。
> 本文是所有实现与验收的**唯一权威依据**；与代码不一致时以本文为准并回改代码。

---

## 1. 目标与范围

### 1.1 目标
- 产出可被 PAOS 安装/启动的 `manifest-v2` Skill：智能体 `activate_skill` 读取 `SKILL.md` → 规划工具调用链 → `gateway` 路由到 Dora Node。
- 仿真闭环：**感知关键点 → VLM 生成约束（沙箱执行）→ 分层优化求解 → 执行 → 视频/结果**。

### 1.2 范围
- 只做仿真；**优先 OmniGibson + Fetch**（与参考实现一致），MuJoCo + Dobot Nova2 作为后续可选 profile。
- 不做真机。
- 不修改 `PhyAgentOS-core`、`rekep-paos`。

### 1.3 非目标
- 不追求论文级全任务泛化；先复现参考插件的 `pen-in-holder` 仿真任务与闭环机制（含反应式重规划）。

## 2. 概念与总览

### 2.1 一个 SKILL 是什么（按手册）
- 智能体经 `activate_skill` 读取 `SKILL.md`，据此规划**工具调用链**；
- `skill.yaml`（manifest-v2）声明 `required_tools`、`profiles`、`gateway_url`、registry node locks；
- `profiles/<p>/gateway.yaml` 用 `tools.specs` 定义每个 Tool 的 `tool_id/endpoint_id/operation/semantics/input|output schema`，`providers` 把 endpoint 接到 Node 的 `tool_in/tool_out`；
- 调用链：`ForgeToolClient → Gateway /tools → ToolInvocation → ToolEndpoint → Dora Node`；
- 智能体**不得臆造** ID/schema，只能调用已声明且 `ready` 的工具。

### 2.2 Node 与 Forge 接入的边界
- **Node**：Dora dataflow 中的可执行单元，实现 Tool 的物理/算法语义。
- **Forge 接入层（非 Node）**：`skill.yaml`、`gateway.yaml`、`dataflow.yaml`、`SKILL.md`、`profiles/`、`assets/`、`start.sh`，以及 PAOS 侧的 AgentTask/verification/evidence。

### 2.3 参考实现
主参考：`https://github.com/baiyu858/PhyAgentOS-rekep-real-plugin`（本地只读副本 `.tmp/opencode/rekep-ref/`）。
- 仿真线：`runtime/environment.py`（OmniGibson+Fetch）、`runtime/main.py`（闭环主循环）、`runtime/keypoint_proposal.py`（DINOv2）、`runtime/constraint_generation.py`（VLM→Python 约束）、`runtime/subgoal_solver.py`/`path_solver.py`/`ik_solver.py`（分层优化+Lula IK）、`runtime/utils.py`（约束执行）、`runtime/vlm_query/prompt_template.txt`（提示词）、`runtime/configs/config.yaml`、`runtime/configs/og_scene_file_pen.json`。
- 真机线（本次 Deferred）：`runtime/real_*`、`dobot_bridge.py`、`robot_factory.py`、`camera_*`、`real_calibration/`、`third_party/`。
- 次要参考：`rekep-paos`（仅看"工具化长什么样"）。

## 3. 架构设计

### 3.1 ReKepEnv 抽象接口（便于换底座）
```
get_cam_obs() -> {cam_id: {rgb, depth, points, seg}}
register_keypoints(positions) / get_keypoint_positions()
get_object_by_keypoint(idx) / is_grasping(obj)
get_sdf_voxels(resolution) / get_collision_points()
get_ee_pose() / get_arm_joint_postions()
execute_action(action8, precise) / open_gripper() / close_gripper()
save_video() / reset() / close()
```
- P1 用 **OmniGibson+Fetch** 实现（关键点提议直接使用 `seg`，SDF 由 USD 网格、IK 用 Lula）。
- 后续 MuJoCo+Dobot 实现同一接口即可替换。
- 注：**仿真线不需要 SAM**（分割来自 OmniGibson `seg`），只依赖 DINOv2 + torch + kmeans + sklearn + scipy + open3d + trimesh + imageio + omnigibson。

### 3.2 Tool 设计（3 个）

| Tool | semantics | 对应参考实现 | 输入 | 输出（要点） |
|---|---|---|---|---|
| `rekep.perception.get_context` | **query** | `keypoint_proposal.py` + `env.get_cam_obs` | `{refresh: bool}` | `observation_id`、`keypoints[{id, position_m, pixel_uv}]`、`objects`、`overlay`、`model/weights digest` |
| `rekep.runtime.plan_task` | **action** | `constraint_generation.py` + `subgoal/path_solver` | `{instruction, observation_id, options}` | `plan_id`、`plan_digest`、`num_stages`、`stages[{subgoal, path, grasp_keypoint, release_keypoint}]`、`vlm_trace`；**不步进仿真** |
| `rekep.runtime.execute_task` | **session** | `main.py:_execute` | `{plan_id, plan_digest, allow_motion: true, deadline_ms}` | `{status, video, result_json, stages, metrics}`；可 `stop` |

### 3.3 Node 设计（2 个进程）
- `rekep-perception`：无状态，承载 `perception/get_context`。
- `rekep-runtime`：有状态，持有 `ReKepEnv + 3 solvers + 约束函数缓存`，承载 `plan_task`、`execute_task`。
- 理由：ReKep 主循环强状态（SDF/碰撞点/EE/keypoints/缓存解每步使用），跨进程同步成本高；与官方 `libero` Skill 的"gateway + 少量 node"同构。

### 3.4 Dataflow（示意）
```yaml
nodes:
  - id: gateway
    path: ${FORGE_RUNTIME_BIN}/gateway
    args: --config gateway.yaml
    inputs:
      tick: dora/timer/millis/50
      perception_tool_in: {source: rekep_perception/tool_out, queue_size: 32}
      runtime_tool_in:    {source: rekep_runtime/tool_out,    queue_size: 32}
    outputs: [tool_response, perception_tool_out, runtime_tool_out]
  - id: rekep_perception
    path: ${FORGE_RUNTIME_BIN}/rekep_perception
    inputs: {tick: dora/timer/millis/100, tool_in: gateway/perception_tool_out}
    outputs: [tool_out]
  - id: rekep_runtime
    path: ${FORGE_RUNTIME_BIN}/rekep_runtime
    inputs: {tick: dora/timer/millis/50, tool_in: gateway/runtime_tool_out}
    outputs: [tool_out]
```

## 4. 沙箱约束执行规范（重点）

VLM 输出形如 `def stageN_{subgoal,path}_constraintM(end_effector, keypoints): ... return cost`。

- **AST 白名单**：仅允许 `FunctionDef / Return / Assign / Expr / BinOp / UnaryOp / Compare / Call / Name / Constant / Subscript / Attribute(受限) / Tuple / List`。
- **禁止**：`Import / If / While / For / With / Lambda / 推导式 / dunder / 属性穿透到内置`。
- **注入**：仅 `np` 与 `get_grasping_cost_by_keypoint_idx`。
- **执行**：`signal` 超时；执行一次做校验。
- **语义校验**（仿 `real_rekep_live._validate_generation_consistency`）：`num_stages > 0`；`grasp/release` 长度 == `num_stages`；`release` 必先 `grasp`；grasp 指向 grasp-like 关键点而非容器/支撑面；约束函数须引用对应关键点。
- 违反任一条 → 稳定错误码（如 `REKEP_CONSTRAINT_REJECTED`）。

## 5. Forge 接入规格

### 5.1 目录
```
rekep-sim/
├── SKILL.md
├── skill.yaml
├── profiles/sim/{dataflow.yaml, gateway.yaml, rekep.yaml, scene.json}
├── assets/                  # 提示词、场景等小资产
├── start.sh                 # 可选：幂等下载 DINOv2 权重
└── scripts/                 # 溯源/打包辅助
```

### 5.2 skill.yaml（要点）
```yaml
manifest_version: 2
name: rekep-sim
version: "0.1.0"
skill_document: SKILL.md
gateway_url: http://127.0.0.1:19201
required_tools: [rekep.perception.get_context, rekep.runtime.plan_task, rekep.runtime.execute_task]
profiles:
  sim:
    dataflow: profiles/sim/dataflow.yaml
    required_binaries: [gateway, rekep_perception, rekep_runtime]
    required_assets: [assets/prompt_template.txt, profiles/sim/scene.json]
    required_environment: [REKEP_VLM_API_KEY]
    environment: {MUJOCO_GL: egl}
artifacts:
  resolver: registry
  nodes:
    gateway: {artifact_id: gateway-1.1.0-linux-x86_64, version: "1.1.0", platform: linux, arch: x86_64, artifact_type: executable_tar_gz, entrypoint: gateway, sha256: <64hex>}
    # rekep_perception / rekep_runtime 同理，单文件
```
约束：node lock 必须含 `artifact_id/version/platform/arch/artifact_type=executable_tar_gz/entrypoint/sha256`。

### 5.3 gateway.yaml（要点）
`agent.enabled: false`、`tools.enabled: true`；三条 ToolSpec（严格 input/output schema、readiness、frame profile）+ `providers`（endpoint ↔ node tool_in/out）。

### 5.4 SKILL.md（要点）
规定：先读 `get_context`；不得臆造 ID；按 `get_context → plan_task → execute_task` 顺序；仅当用户要求执行才 `allow_motion=true`；如实汇报 `status`/`video`；错误时停止并上报，不自动重试物理执行。**不嵌入坐标与密钥**。

### 5.5 重依赖策略
- Node 采用 **thin-freeze 单文件**；OmniGibson/torch/Lula 等重依赖由宿主 venv 提供（仿 calvin 的 `*_HOST_SITE` 注入）。
- DINOv2 权重等大资产由 `start.sh` 幂等下载（已存在则跳过，断点续传，校验 sha256）。

## 7. 环境与硬约束（必须遵守）

### 7.1 根盘保护
本机 `/`（含 `/tmp`、`/root`）仅剩约 4.7G，`/data7` 余 1.7T。所有状态、缓存、构建、下载**必须**在 `/data7`。`scripts/env.sh` 统一设置：
```
TMPDIR / PIP_CACHE_DIR / PIP_TMPDIR / UV_CACHE_DIR
XDG_CACHE_HOME / XDG_DATA_HOME / HF_HOME / TORCH_HOME
CONDA_PKGS_DIRS / PYTHONPYCACHEPREFIX / PAOS_HOME
OMNIGIBSON/Isaac 数据目录
```
验收：执行前后 `df /` 不下降；无写入 `/tmp`、`/root`。

### 7.2 版本基线
- PhyAgentOS `v1.0.0`（main 2026-09-11）；Dora `0.4.1` / dora-message `0.7.0`。
- Node：单文件 `executable_tar_gz`；本机 Ubuntu 20.04 / glibc 2.31 构建，对目标 2.35 前向兼容。
- 复用注册的 `gateway-1.1.0`（归档内恰好 `gateway` 一个文件，仅需 GLIBC_2.14）。
- **已确认（P1）**：当前 PAOS 1.0.0（含本机已安装版）只接受单文件 `executable_tar_gz`，不支持 `directory_tar_gz`。
- **已确认（P1）**：构建主机 glibc 2.31 不支持 `os.chmod(follow_symlinks=False)`，PAOS 原生安装会失败 → 本地开发用 `scripts/shim/sitecustomize.py` 非侵入式 shim；生产安装/运行在 glibc ≥ 2.32（目标 2.35）执行。

## 9. 风险与回滚
- OmniGibson/Isaac headless 体积与 Python 版本适配风险；装不上则前移 MuJoCo 备选。
- VLM 非确定 → 确定性测试用**冻结程序**（仿 `--use_cached_query`）。
- 沙箱安全为红线（原 `exec_safe` 仅禁 `import`/`__`，不足）。
- 仿真线副作用（写 `videos/`、`vlm_query/<ts>_*`）改为写入 PAOS 工作区并纳入证据。
- 回滚：源码形态 + 本地 deploy 脚本开发；打包发布走不可变版本，失败保留旧版本。

## 附录 A：P1 实测修订（2026-09-21）

- **仿真底座决策依据**：Isaac Sim pip 安装要求 **glibc ≥ 2.35**，本构建主机 2.31 → **OmniGibson 无法在本机安装**；已具备 8×RTX 3090 与 EGL/OSMesa。因此本地开发建议改用 **MuJoCo** 实现 `ReKepEnv`（算法照搬，env 换实现；可复用 rekep-paos 的 Dobot Nova2 MuJoCo 资产）；OmniGibson 高保真版仅在 2.35 服务器可选。
- **Node 契约已实测**：官方 `package_skill.py` → `paos skill install --local` → `paos forge-node install/verify` → `inspect` 全通过；`gateway-1.1.0` 归档内恰好 `gateway` 一个文件。
- **根盘零增长**：全程 `/` 用量不变（8.5G）；所有状态在 `/data7`（缓存 `.paos-rekep/`、PAOS_HOME `~/.PhyAgentOS`、模型 `.paos-rekep/models/`）。
- **版本锁定**：PhyAgentOS v1.0.0；dora 0.4.1 / 0.7.0；DINOv2 源码 `7764ea0f`、权重 sha256 `b938bf1b…`；gateway sha256 `bb42c141…`。
