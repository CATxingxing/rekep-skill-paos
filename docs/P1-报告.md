## 3. 两个硬发现（影响架构，必须处理）

### 3.1 构建主机 glibc 2.31 不支持 `os.chmod(..., follow_symlinks=False)`
- 现象：`ArchiveValidator.extract`（`archive.py:202`）抛 `NotImplementedError: chmod: follow_symlinks unavailable on this platform`。
- 根因：glibc < 2.32 的 `fchmodat(AT_SYMLINK_NOFOLLOW)` 不可用，本机所有 Python（3.8/3.11）均报告 `os.chmod not in os.supports_follow_symlinks`。
- 影响：**当前 PAOS 1.0.0 无法在 Ubuntu 20.04 上原生安装/解包 bundle**；目标运行机（glibc 2.35 / Ubuntu 22.04）不受影响。
- 处置：本地开发用**非侵入式 shim**（`scripts/shim/sitecustomize.py` + `scripts/paos_dev_shim.py`，仅 patch 进程，不改 PAOS-core）；**生产安装/运行在 glibc ≥ 2.32 的目标机执行**。

### 3.2 OmniGibson / Isaac Sim 无法在本构建主机安装
- Isaac Sim **pip 安装要求 glibc ≥ 2.35**（`manylinux_2_35`）；本机 2.31 → 装不了。
- 版本对应：Isaac Sim 5.x → Python 3.11；Isaac Sim 4.x → Python 3.10；磁盘约 50GB；需 NVIDIA 索引 + EULA。
- 本机虽有 8×RTX 3090（24GB，驱动 550.54.15），但 pip 路径被 glibc 阻断。
- 结论：要在本机跑仿真，**不能依赖 OmniGibson**。

## 4. 对方案的影响与建议
- **仿真底座建议改为 MuJoCo（本地可跑）**：glibc 2.31 可 pip 安装 mjoco，EGL/OSMesa 已就绪；复用参考实现的**算法**（DINOv2 关键点、VLM 约束、subgoal/path 分层优化），仅把 `ReKepEnv` 换成 MuJoCo 实现（可复用 rekep-paos 的 Dobot Nova2 MuJoCo 资产）。
- **或**：保留 OmniGibson 高保真实现，但**只在 glibc 2.35 服务器**安装/运行（本机仅构建 node）。
- 两方案对 Skill/Node/Forge 协议层**无差别**（都通过 `ReKepEnv` 接口隔离）。
